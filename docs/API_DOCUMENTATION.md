# API Documentation

Base URL: `http://localhost:8000/api/v1` (local) or
`https://<your-render-service>.onrender.com/api/v1` (production).

Interactive docs are also auto-generated by FastAPI at `/docs` (Swagger UI)
and `/redoc`.

## Authentication (Interim)

Every endpoint below except `/health` and `/google/oauth/callback` requires
an `X-User-Id` header set to the caller's Supabase `users.id`. This is a
temporary stand-in for Firebase JWT auth (see README roadmap) — the header
name and semantics won't change when real auth lands, only how the ID is
verified.

```
X-User-Id: <uuid>
```

## Error Shape

All errors return:

```json
{
  "error": {
    "code": "some_error_code",
    "message": "Human-readable description.",
    "request_id": "uuid-for-log-correlation"
  }
}
```

`request_id` also appears as the `X-Request-ID` response header on every
request (success or failure) — include it when reporting issues.

## Agent (Multi-Agent System)

| Method | Path | Description |
|---|---|---|
| POST | `/agent/chat` | Send a message. Coordinator Agent routes it (or pass `agent_name` to force a specific agent). Body: `{message, chat_id?, agent_name?}`. Returns `{run_id, chat_id, answer, status, agent_name}`. |
| GET | `/agent/agents` | List available specialized agents (`key`, `display_name`, `description`). |
| GET | `/agent/runs?chat_id=` | List recent agent runs for the user. |
| GET | `/agent/runs/{run_id}/timeline` | Full step-by-step execution log for a run (route/plan/tool_call/tool_result/retry/error/final_answer). |
| GET | `/agent/chats` | List the user's chats. |

Valid `agent_name` values: `assistant_agent`, `email_agent`,
`calendar_agent`, `research_agent`, `vision_agent`, `notes_agent`,
`task_agent`.

## Files (Intelligence)

| Method | Path | Description |
|---|---|---|
| POST | `/files/upload` | Multipart: `file`, optional `chat_id`. Accepts PDF/DOCX/TXT/CSV/XLSX/XLS and PNG/JPG/JPEG/WEBP/GIF. Max 20 MB (`MAX_UPLOAD_BYTES`). |
| GET | `/files?chat_id=` | List uploaded files (id, name, type, summary). |
| GET | `/files/{file_id}` | Extracted text content (documents only — images 400 here, use Vision endpoints). |
| POST | `/files/{file_id}/summarize` | Generates and persists a summary. |
| POST | `/files/{file_id}/ask` | Body: `{question}`. Answer grounded strictly in the document. |

## Vision

All operate on a `file_id` from `/files/upload` (must be an image type).

| Method | Path | Description |
|---|---|---|
| POST | `/vision/analyze/{file_id}` | Body: `{prompt?}`. General image description or a focused question. |
| POST | `/vision/ocr/{file_id}` | Extract all readable text. |
| POST | `/vision/screenshot/{file_id}` | Body: `{question?}`. UI/screenshot-specific analysis. |
| POST | `/vision/chart/{file_id}` | Body: `{question?}`. Chart/graph-specific analysis. |

## Voice

| Method | Path | Description |
|---|---|---|
| POST | `/voice/transcribe` | Multipart: `file` (audio). Returns `{transcript}`. |
| POST | `/voice/synthesize` | Body: `{text, voice_name?, language_code?}`. Returns raw `audio/mpeg` bytes. |
| POST | `/voice/chat` | Multipart: `file` (audio), optional `chat_id`. Full round trip: transcribe → agent run → synthesize. Returns `{run_id, chat_id, transcript, answer, answer_audio_base64}`. |
| WS | `/voice/stream` | Real-time streaming STT. Send binary audio chunks (WebM/Opus, ~250ms each); receive `{"transcript": str, "is_final": bool}` JSON messages. |

## Rate Limits & Timeouts

No application-level rate limiting is enforced yet (`slowapi` is available
as a dependency for a future phase). External calls (Gemini, Google APIs,
weather, web search) use `tenacity`-backed retry with exponential backoff
where applicable; agent tool calls additionally retry per the agent's
`max_retries` (default 2) with each attempt logged to the execution timeline.
